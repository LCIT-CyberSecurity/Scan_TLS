# MCP server (read-only)

TLS Scan embeds a **Model Context Protocol** server so that a compatible AI assistant can consult scan results. It uses the official Python SDK, the **Streamable HTTP**
transport, at exactly `/mcp`, inside the existing API process and reverse proxy (no extra container). Name: **TLS Scan MCP**.

* **Off by default**, independently of the [external REST API](external-api.md). It answers only when an administrator enabled **MCP server** (*Administration → Settings*) **and** authorised your account (*Administration → Users → MCP*).
* **Read-only and closed**: eight tools over scan results. No scan launch, no write, no export or report generation, no shell, SQL, file-system or arbitrary HTTP access, no connector or settings management, no secrets.
* **Authentication**: `Authorization: Bearer tls_scan_mcp_<secret>`. The key is generated by its owner in *Preferences → API and MCP access* (shown once, valid 90 days, one active key, revocable). Only its SHA-256 is stored.
  A REST key (`tls_scan_pat_…`) is refused here and an MCP key is refused by every other surface.
* **Every HTTP request and every tool call** re-validates the global switch, the key, expiry/revocation, the active user, the individual authorisation and the **current role**.

## Tools

| Tool | Parameters | Result |
|---|---|---|
| `tls_scan_get_current_user` | – | id, e-mail, name, current role |
| `tls_scan_list_scans` | `limit` (1-100), `offset`, `status`, `mine` | page of scans (same schema as REST) |
| `tls_scan_get_scan_summary` | `scan_id` | scan detail with engine statistics |
| `tls_scan_list_endpoints` | `scan_id`, `limit`, `offset`, `compliance_status`, `severity`, `q` | page of TLS endpoints |
| `tls_scan_get_endpoint_details` | `scan_id`, `endpoint_id` | one endpoint (certificate, cipher suites) and the findings that affect it |
| `tls_scan_list_findings` | `scan_id`, `limit`, `offset`, `severity`, `category`, `status`, `endpoint_id` | page of findings |
| `tls_scan_get_compliance_summary` | `scan_id` | engine summary and endpoint counts by compliance status and by highest severity |
| `tls_scan_compare_scans` | `scan_id`, `with_scan_id` (optional) | new / fixed / persistent / not-retested findings and endpoint changes. USER role or higher |

Results use the same schemas and visibility rules as the [external REST API](external-api.md): a user never sees more through MCP than through the equivalent application access. Pages are bounded (100 items);
an unknown, invalid or not-visible id gives the same generic error.

## Transport security

* **Host and Origin validation** (DNS-rebinding protection): allowed hosts are `localhost`, loopback, the container name and the host of `TLS_SCAN_PUBLIC_BASE_URL`; extend with `TLS_SCAN_MCP_ALLOWED_HOSTS` / `TLS_SCAN_MCP_ALLOWED_ORIGINS` (comma-separated, `*` port wildcards allowed). Unknown `Origin` → `403`.
* Request bodies are limited to 64 KB; tool calls time out after 25 s; limits of 240 HTTP requests and 60 tool calls per minute per key (`429`).
* Use HTTPS for any remote connection. The bundled nginx proxies `/mcp` (streaming, no buffering) to the API.
* Calls are audited (`mcp.tool_called`, `mcp.tool_denied`, `mcp.auth_failed`, `mcp.rate_limited`): user, tool, scan id, result count, duration, key prefix — never the key.

## Connecting a client

Any MCP client that supports Streamable HTTP and custom headers. Example configuration:

```json
{
  "mcpServers": {
    "tls-scan": {
      "type": "http",
      "url": "https://tls-scan.example.org:8443/mcp",
      "headers": { "Authorization": "Bearer tls_scan_mcp_…" }
    }
  }
}
```

With the official Python SDK:

```python
from mcp import ClientSession
from mcp.client.streamable_http import streamable_http_client
import httpx2

async with httpx2.AsyncClient(headers={"Authorization": "Bearer tls_scan_mcp_…"}) as http:
    async with streamable_http_client("https://tls-scan.example.org:8443/mcp", http_client=http) as streams:
        async with ClientSession(*streams[:2]) as session:
            await session.initialize()
            print((await session.call_tool("tls_scan_list_scans", {"limit": 5})).structured_content)
```

## Errors

A refused HTTP request is `401` (key, service or authorisation), `403` (Origin), `421`/`400` (Host), `413` (body too large), `429` (rate limit). A tool error (unknown scan, invalid parameter, insufficient role) is returned as a tool result with `isError` set.
See also [administration](../admin/operations.md#external-api-and-mcp-access).

## Complementary TLS checks

`tls_scan_list_endpoints` and `tls_scan_get_endpoint_details` include `tls_checks` for each endpoint (same structure as the REST API:
[details](external-api.md#complementary-tls-checks)). They never change the grade or compliance fields.
